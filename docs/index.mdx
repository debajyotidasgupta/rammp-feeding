# Robot-assisted feeding

`rammp_feeding` feeds a seated user from a bowl, with a fork in the Kinova Gen3's gripper. Each bite:
1. **The bowl:** the scene camera gives a first look, and the wrist camera finds the bowl and centres over it.
2. **The pick:** the wrist camera picks a piece. The fork plunges, scoops and lifts it.
3. **The delivery:** the arm swings to the delivery look, waits for an open mouth, measures it, presents the piece,
   waits for the bite and returns.

It repeats until the bowl is empty or the user declines. It is one RAMMP node. Every move goes through the arm node.
Free-space moves are the shared RAMMP-CuRobo planner's paths, checked by us for the fork. Straight-line and contact
moves are computed on the arm's model. It never commands the gripper.

Deploying: the [deployment checklist](porting.md). ROS interfaces: the [interface reference](interface.md).

## Commands
`rammp <command>`, by hand. Under sheppy, the `feeding` node is a capability engine: the orchestrator starts its
actions (`start_meal`, `feed` for one bite, `finish_meal`) and nothing moves otherwise ([interface](interface.md)).

| Command | What it does |
| --- | --- |
| `check` | Every node, measurement and capture the module needs. Never moves. |
| `state` | Where the arm is. Never moves. |
| `home [--direct]` | To feeding_start: a planned path, or one joint move with `--direct` (clear workspace only). |
| `setup [step ...]` | After the arm, the bowl or the user moved: guided captures and calibrations (site, home, scene, overlook, bowl, deliver). |
| `locate-scene` | The bowl and the table from the scene camera. Never moves. |
| `detect` | Over the bowl, centred by the wrist camera. |
| `perceive` | The target piece (a new bite). Never moves. |
| `acquire [--stop-after over\|hover30\|hover10\|plunge] [--start-at over\|scoop]` | Over the piece, plunge, scoop, lift. |
| `rise` | Straight up to the overlook height. |
| `deliver [--stop-after swing\|present\|bite] [--start-at swing\|present\|bite\|retract]` | Swing, present, bite, retract. |
| `retract` | From the user back over the bowl. |
| `feed [--bites N]` | Locate, detect, then bites until done, then home. |
| `calibrate-wrist [--board]` | The wrist camera's mount and the fork's pixels, from the ChArUco board (`--board`: the sheet to print). |
| `calibrate-scene` | The scene camera's pose through the board. |
| `capture home\|overlook\|deliver` | The arm's joints now as that pose. Never moves. |

A command that cannot proceed refuses with the reason and leaves the arm still. Every command can be run again.

## Exit codes

| Code | Meaning |
| --- | --- |
| 0 | Done (`feed`: also when the bowl is empty or the user declines) |
| 1 | Stopped or refused; the log's `STOPPED:` line says why |
| 3 | The bowl is empty |
| 4 | No bite in `delivery.bite_timeout_s` (retracted with the piece) |
| 5 | Food is left but no piece is pickable |
| 7 | The user did not open their mouth (retracted) |
| 8 | No usable mouth, or one the arm cannot reach (retracted) |

## The run record
Each command writes `<runs>/<YYYYmmdd_HHMMSS>_<command>/`, which holds `log.txt`, `events.jsonl`, the merged
`config.yaml`, and one `bite_NN/` per bite with each stage's images and telemetry. `<runs>/latest` points at the
current bite, so a stage run on its own continues it.
