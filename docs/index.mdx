# Robot-assisted feeding

`rammp_feeding` feeds a seated user from a bowl, with a fork in the Kinova Gen3's gripper. Each bite:
1. **The bowl:** the scene camera gives a first look (with none, where the bowl is laid), and the wrist camera finds
   the bowl and centres over it.
2. **The pick:** the wrist camera picks a piece. The fork plunges, scoops and lifts it.
3. **The delivery:** the arm swings to the delivery look, waits for an open mouth, measures it, presents the piece,
   waits for the bite and returns.

It repeats until the bowl is empty or the user declines. It is one RAMMP node. Every move goes through the arm node.
Free-space moves are the shared RAMMP-CuRobo planner's paths; one that sweeps a joint round is planned again.
Straight-line and contact moves are computed on the arm's model. Both kinds are checked, before they run, against one
collision world: the table, the bowl, the user once measured, and the fork's stand once found. The planner checks the
arm's links; we check the fork's tip and length on every path. It commands the gripper only to pick the fork up from
its stand and put it back (pick_up_fork, put_down_fork).

Deploying: the [deployment checklist](porting.md). ROS interfaces: the [interface reference](interface.md).

## Commands
`rammp <command>`, by hand. Under sheppy, the `feeding` node is a capability engine: the orchestrator starts its
actions (`start_meal`, `feed` for one bite, `finish_meal`) and nothing moves otherwise ([interface](interface.md)).

| Command | What it does |
| --- | --- |
| `check` | Every node, measurement and capture the module needs. Never moves. |
| `state` | Where the arm is. Never moves. |
| `home [--direct]` | To feeding_start: a planned path, or one joint move with `--direct` (clear workspace only). |
| `setup [step ...]` | After the arm, the bowl or the user moved: guided captures and calibrations (site, home, scene, overlook, bowl, deliver). |
| `locate-scene` | The bowl and the table from the scene camera (with none, where the bowl is laid). Never moves. |
| `detect` | Over the bowl, centred by the wrist camera. |
| `perceive` | The target piece (a new bite). Never moves. |
| `acquire [--stop-after over\|hover30\|hover10\|plunge] [--start-at over\|scoop]` | Over the piece, plunge, scoop, lift. |
| `rise` | Straight up to the overlook height. |
| `deliver [--stop-after swing\|present\|bite] [--start-at swing\|present\|bite\|retract]` | Swing, present, bite, retract. |
| `retract` | From the user back over the bowl. |
| `feed [--bites N]` | Locate, detect, then bites until done, then home. |
| `calibrate-wrist [--board]` | The wrist camera's mount and the fork's pixels, from the ChArUco board (`--board`: the sheet to print). |
| `calibrate-scene` | The scene camera's pose through the board. |
| `capture home\|overlook\|deliver\|fork_look` | The arm's joints now as that pose. Never moves. |
| `pick-fork [--start-at S] [--stop-after S]` | The fork picked up from its stand, then home. Steps: `look`, `hover`, `in`, `hold`, `lift`, `out`. |
| `put-fork [--start-at S] [--stop-after S]` | The fork hung back on its stand, then home. Steps: `back`, `lower`, `release`, `up`. |
| `find-fork` | At fork_look: the opening, and whether the way in is reachable. Never moves. |
| `gripper open\|close` | The fingers opened (the fork held) or closed (not held). In the opening after a stopped step, that step by hand. |
| `tip DX DY` | The tip seen DX, DY m (base frame) off where the model puts it: the model moved to match. Never moves. |

A command that cannot proceed refuses with the reason and leaves the arm still. Every command can be run again.
Ctrl-C, or `rammp-stop` from another terminal ([porting](porting.md)), cancels the move in flight.

### The fork's steps
| Step | Pick (`pick-fork`) |
| --- | --- |
| `look` | Fingers closed; to fork_look over the stand |
| `hover` | The opening found; over it, `above_m` above the rim, the fingers along its long side |
| `in` | Straight down, `insert_m` under the rim |
| `hold` | Fingers opened until the opening's walls stop them |
| `lift` | Straight up `lift_m` |
| `out` | A side holder: out through its open side, the empty stand's strip read. Then a firm hold |

| Step | Put-back (`put-fork`) |
| --- | --- |
| `back` | A top holder: back to where the lift ended. A side holder: the strip found, in through the open side over the seat |
| `lower` | Straight down onto the seat |
| `release` | Fingers closed: the fork let go |
| `up` | Straight up out of the opening |

`utensil.pick.holder` is `side` (the fork leaves through an open side, the lab's stand) or `top` (straight up and
down, a box holder). A first try at a new or moved stand: `rammp pick-fork --stop-after hover`, check the fingers
are centred over the opening, then `rammp pick-fork --start-at in`.

### Small moves by hand
One slow move each, from wherever the arm is, checked against the world like the module's own moves (a move into the
bowl, the stand or the user names it with `--into bowl,stand,user`). Distances in metres, angles in degrees.

| Command | What it does |
| --- | --- |
| `move DX DY DZ` | The tool straight by (DX, DY, DZ), base frame (x away from the base, z up), its orientation kept |
| `up D` / `down D` | Straight up / down by D |
| `turn DEG` | Turned about the vertical through the tip, counter-clockwise seen from above |
| `point-down` | Turned about the tip until the tool points straight down |
| `joint J DEG` | Joint J (1-7) alone by DEG |

A move longer than `motion.jog.max_m` (0.20 m) or a turn past `motion.jog.max_deg` (90) is refused.

## Fakes
Any sensing can be a stand-in, set in `local.yaml` under `fakes:`; the arm, the planner and the gripper stay real, so
the arm moves to the fake things through the same moves and checks:

| Setting | Stands in for |
| --- | --- |
| `fakes.food: {pieces_m: [[x, y], ...]}` | SAM3 and the depth: pieces lying in the bowl, taken one per bite until the bowl is empty |
| `fakes.mouth: {at_m: [x, y, z]}` | MediaPipe: the user's mouth, open after `fakes.open_after_s`; the bite felt after `fakes.bite_after_s` |
| `fakes.holder: {centre_m: [x, y, z], long_deg: a}` | SAM3 on the fork's stand: its opening's centre at the rim and its long side |

Remove a setting to go back to the real sensing. In code, `rammp_feeding/sensing.py` hands out each sensing function,
real or fake; `sensing.use(...)` puts a test's own in place.

## Exit codes

| Code | Meaning |
| --- | --- |
| 0 | Done (`feed`: also when the bowl is empty or the user declines) |
| 1 | Stopped or refused; the log's `STOPPED:` line says why |
| 3 | The bowl is empty |
| 4 | No bite in `delivery.bite_timeout_s` (retracted with the piece) |
| 5 | Food is left but no piece is pickable |
| 7 | The user did not open their mouth (retracted) |
| 8 | No usable mouth, or one the arm cannot reach (retracted) |

## The run record
Each command writes `<runs>/<YYYYmmdd_HHMMSS>_<command>/`, which holds `log.txt`, `events.jsonl`, the merged
`config.yaml`, and one `bite_NN/` per bite with each stage's images and telemetry. `<runs>/latest` points at the
current bite, so a stage run on its own continues it.
